# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

AI-Usage is the canonical source for AI assets (skills, rules, agents, principles). It holds the authored YAML, transforms it into each AI tool's native config, and builds an Astro documentation site and an outputs hub that deploy to GitHub Pages. Almost all logic is PowerShell (`scripts/`). The only Node project is `site/`.

## Commands

Run PowerShell commands from the repo root.

```powershell
# Validate canonical assets only (no writes). Exits non-zero on failure.
.\scripts\sync.ps1 -ValidateOnly

# Preview a sync without writing anything. Always run this before a real sync.
.\scripts\sync.ps1 -DryRun

# Sync to one target: antigravity | cursor | claude | gemini | site | all (default)
.\scripts\sync.ps1 -Target cursor

# Regenerate only the site JSON catalogs (site/src/data/*.json)
.\scripts\sync.ps1 -Target site

# Scaffold a new canonical asset (validates it afterwards)
.\scripts\new-asset.ps1 -Type skill -Name my-skill -Description "Use this skill when ..."
```

Site (Astro 5, `site/`):

```powershell
cd site
npm install
npm run dev      # dev server; base path is /AI-Usage/
npm run build    # static build to site/dist
```

- There is no test suite and no lint configuration. There is no single-test command to run.
- `site/tsconfig.json` extends `astro/tsconfigs/strict`, but no npm script runs a type check.
- `sync.ps1 -AssetType` is declared but never read. Only `-Target`, `-DryRun` and `-ValidateOnly` have an effect.

## Architecture

### Canonical assets are the source of truth (`assets/`)

- Skills live in folders: `assets/skills/<name>/skill.yaml`, plus optional `references/`, `scripts/` and `examples/` subfolders. Discovery is recursive on `skill.yaml`.
- Rules, agents and principles are flat files: `assets/{rules,agents,principles}/<name>.yaml`. These folders are currently empty. Only skills exist.
- Each `skill.yaml` has a `meta:` block, a `targets:` block and a `content: |` markdown block. Skill steps are read from `### N. Title` headings inside `content`.

### The YAML "parser" is line-based and key-specific

`scripts/utils/yaml-parser.ps1` (`Parse-CanonicalYaml`) is not a real YAML parser. It recognizes a fixed list of keys: `name`, `version`, `description`, `tags`, `scope`, `priority`, `role`, `category`, `alwaysApply`, `globs`, `capabilities`, `skills_required`, `rules_applied`, and the `content: |` and `system_prompt: |` blocks. Any new field is silently ignored until the parser is updated. Changing the parser affects every transform.

### Validation gates every sync

`sync.ps1` always runs `scripts/utils/validate.ps1` first and aborts on failure. Validation is hardcoded: skill names must be lowercase kebab-case, descriptions must be at least 20 characters, and a `content` block is required. The JSON schemas in `contracts/schemas/` and the YAML files in `contracts/` are not read by any script. Treat them as documentation unless you wire them in.

### One transform per tool (`scripts/transforms/`)

Each transform reads `assets/` and writes to a user-home location outside the repo:

| Transform | Asset types | Output |
| :--- | :--- | :--- |
| `to-antigravity.ps1` | skills, rules | `~/.gemini/config/skills/<name>/SKILL.md` (also copies `references/`, `scripts/`, `examples/`) and `~/.gemini/config/rules/AGENTS.md` |
| `to-cursor.ps1` | rules only | `~/.cursor/rules/<name>.mdc` |
| `to-claude-code.ps1` | skills, rules | `~/.claude/skills/<name>/SKILL.md` (also copies `references/`, `scripts/`, `examples/`) and `~/.claude/CLAUDE.md` |
| `to-gemini-cli.ps1` | rules only | `~/.gemini/GEMINI.md` |
| `to-site.ps1` | all four types | `site/src/data/{skills,rules,agents,principles}.json` |

Skills are synced to Antigravity and Claude Code only. Cursor and Gemini CLI get rules only. The `targets:` block in `skill.yaml` is not read by any transform.

### Site and outputs

- `site/` is an Astro static site with base `/AI-Usage/`. Pages in `site/src/pages/` read the generated JSON in `site/src/data/`. The UI is built from `site/src/components/Clay*.astro` and styled by `site/src/styles/clay.css`.
- `site/src/data/*.json` is generated by `to-site.ps1` and committed to git. Regenerate it with `sync.ps1 -Target site`. Do not hand-edit it.
- `outputs/` (research HTML, reports, experiments) is not part of the Astro build. The deploy workflow copies it into `site/public/outputs/` at build time.
- `.github/workflows/deploy.yml` runs on every push to `main`: it copies outputs, runs `npm install`, runs `to-site.ps1`, runs `npm run build`, and deploys `site/dist` to GitHub Pages.

### Bridge skills delegate to external checkouts

`archify` and `humanizer` are thin bridges. Their `skill.yaml` and `references/*-bridge.md` point to local checkouts at `D:\IT\archify\archify` and `D:\IT\humanizer`, overridable with `ARCHIFY_HOME` and `HUMANIZER_HOME`. Upstream content is deliberately not copied into this repo. Do not edit those upstream checkouts from this repo. The scripts in each skill's `scripts/` folder resolve those paths.

## Gotchas

- `sync.ps1` without `-DryRun` writes to real user-home configs. `to-claude-code.ps1` and `to-gemini-cli.ps1` overwrite `~/.claude/CLAUDE.md` and `~/.gemini/GEMINI.md` entirely. Anything hand-written in those files is lost.
- Line endings: `*.ps1` must be CRLF and everything else LF (see `.gitattributes` and `.editorconfig`).
