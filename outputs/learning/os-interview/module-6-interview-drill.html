2. Senior Production Debugging Scenarios

Senior

🔥 Case A: 100% System CPU in epoll_wait

Symptom: High-throughput TCP proxy spikes to 100% sys CPU while throughput stalls.

Root Cause & Fix: Multiple worker threads sharing one epoll set cause a Thundering Herd—every thread wakes for 1 packet, contends on kernel locks, and goes back to sleep. Fix with EPOLLEXCLUSIVE or per-core SO_REUSEPORT.

Senior

🐢 Case B: Load Average 48, CPU Idle 85%

Symptom: API latencies jump to 10s, top shows Load Avg 48 on an 8-core box, yet CPU is mostly idle.

Root Cause & Fix: Linux Load Average counts D-state (Uninterruptible I/O sleep) tasks! Check vmstat 1 for high wa (iowait) & b—either swap Thrashing or stalled disk/NFS storage.

Senior

💥 Case C: Redis OOM Crash During Backup

Symptom: A 10 GB Redis instance on a 16 GB host gets killed by Linux OOM Killer right during BGSAVE.

Root Cause & Fix: BGSAVE calls fork(). Heavy writes in the parent dirty Copy-on-Write pages, pushing total physical RAM toward 20 GB! Fix by sizing RAM to 2× peak dataset or pausing heavy writes during snapshots.

Mid

💾 Case D: Deleted 50 GB Log, Disk Still 100% Full

Symptom: rm app.log succeeds, yet df -h shows 0 bytes freed.

Root Cause & Fix: A running daemon still holds an open File Descriptor to that inode. Run lsof +L1 and signal the service to reopen logs (kill -USR1) or truncate via : > app.log.
