Module 3: Virtual Memory, Paging, Stack/Heap & Allocators

Interactive Lesson Date: 2026-11-14 Agent: cs-mentor Fresher → Senior

How can two running apps both believe their variable sits at address 0x601000 without crashing into each other? Why does malloc(10GB) succeed on a 4 GB laptop? Let's demystify Virtual Memory!

1. Daily-Life Analogies: The Hotel Room Map & Shared Gym

🏨 Virtual Memory = Every Guest Gets Their Own "Room 101"

Guest A and Guest B both think they live in "Room 101" (Virtual Address). Only the Hotel Front Desk (MMU + Page Table) knows Guest A's Room 101 is actually Physical Suite #408 and Guest B's Room 101 is Physical Suite #912!

🏋️ Shared Libraries (libc) = One Hotel Gym

Even though Guest A calls it "Floor 3" and Guest B calls it "Floor 9", the Front Desk maps both virtual maps to the same physical gym room in RAM—saving gigabytes of duplicate code across hundreds of processes.

🥞 Stack vs. Heap = Cafeteria Tray Stack vs. Warehouse

Stack is fast LIFO plates: push on function entry, pop on return, tiny (~8 MB). Heap is a giant storage warehouse: ask the manager (malloc/GC) for a custom shelf of any size, keep it as long as you want, clean it up carefully.

📦 Thrashing = Moving Boxes All Day, Doing Zero Work

If your desk only fits 3 folders (RAM) and you need 10 folders constantly, you spend 99% of your day walking to the basement storage room (Swap Disk) and 1% actually reading!

3. Interview Question Deep-Dive (Fresher → Senior)

Fresher Core OS

Q1. Stack vs. Heap Space + What happens in memory when you launch an app?

🎙️ 30-Second Answer: "The Stack is per-thread, LIFO-managed, ultra-fast (just moves a CPU stack pointer), and stores local variables and call frames. The Heap is shared across threads, dynamically allocated (malloc/new), and lives until freed or garbage-collected. When you launch an app, the OS loader creates a fresh virtual address space, maps the binary's Text/Data segments and shared libraries lazily (without loading the whole file into RAM upfront!), sets up an initial Stack, and jumps to _start."
Fresher Core OS

Q2. What is Virtual Memory, and why do we need it?

🎙️ 30-Second Answer: "Virtual Memory is an abstraction layer giving every process its own private, contiguous-looking address space backed by fragmented physical RAM and disk swap. We need it for three reasons: 1) Isolation & Security (Process A can't read Process B's secrets), 2) Simplicity (compilers always use predictable addresses), and 3) Efficiency (only actively used pages live in RAM, and libraries can be shared)."
Junior Core OS

Q3. How does Virtual Memory work (MMU, Page Tables, TLB) & how large is it?

🎙️ 30-Second Answer: "The CPU's MMU translates every Virtual Address into a Physical Address using per-process multi-level Page Tables (usually 4KB pages). To avoid slow RAM lookups on every instruction, the MMU caches hot translations inside the TLB (Translation Lookaside Buffer). Size-wise: a 32-bit OS has a 4 GB virtual address space; a 64-bit x86-64 CPU typically uses 48-bit virtual addresses = 256 TB per process!"
Junior Core OS

Q4. What is Paging & a Page Fault (Minor vs. Major)?

🎙️ 30-Second Answer: "Paging divides virtual memory into fixed-size Pages (usually 4 KB) and physical RAM into matching Frames, eliminating external RAM fragmentation. A Page Fault fires when code accesses a valid virtual page not yet mapped in the page table: a Minor Fault resolves in RAM (e.g., lazy zero-page allocation or shared cache), while a Major Fault must fetch the page from disk/swap—thousands of times slower."
Mid Core OS

Q5. Can 2 processes touch each other's address space? Trap: Can 2 processes map to the SAME physical address?

🎙️ 30-Second Answer: "By default, no—two processes cannot arbitrarily read or modify each other's virtual memory because their Page Tables point to completely separate physical frames. HOWEVER, two processes very commonly map different virtual addresses to the same physical address intentionally: via Shared Memory (shm), mmap(), Copy-on-Write after fork(), and Shared Libraries (libc)!"
⚠️ Classic Interview Confusion: Separate virtual address spaces ≠ zero shared physical RAM! Virtual memory isolates unless the kernel explicitly maps two PTEs to the same physical frame.
Mid Core OS

Q6. How do 2 processes share the same library (e.g., libc) without duplicating RAM?

🎙️ 30-Second Answer: "Shared libraries (.so / .dll) are compiled as Position-Independent Code (PIC). The OS loads libc's read-only machine code (.text) into physical RAM once and maps those same physical frames into every process's virtual address space—even at different virtual addresses (ASLR). Only each process's writable global data (.data / GOT) gets private Copy-on-Write pages."
Junior Production

Q7. Page Replacement (LRU / Clock) & What is Thrashing?

🎙️ 30-Second Answer: "When RAM is full, the OS evicts pages using approximations of LRU like the Clock (Second-Chance) algorithm. Thrashing occurs when the combined Working Set (actively needed pages) of running apps exceeds physical RAM: the OS constantly swaps pages in and out of disk, CPU utilization collapses, and iowait skyrockets."
Mid Internals

Q8. Internal vs. External Fragmentation & brk() vs. mmap()

🎙️ 30-Second Answer: "Internal fragmentation is wasted space inside an allocated block (e.g., allocating 100 bytes inside a 4KB page). External fragmentation is free memory split into tiny non-contiguous holes between allocations. In user-space allocators, small allocations grow the heap via brk(), while huge allocations (>128KB in glibc) use mmap() so they can be cleanly unmapped back to the OS on free()."
Senior Production

Q9. ptmalloc vs. jemalloc, Lazy Demand Paging & Linux OOM Killer

🎙️ 30-Second Answer: "malloc() only reserves virtual address space—physical RAM isn't committed until your code actually writes to those pages (Demand Paging). Because Linux enables Memory Overcommit by default, apps can allocate more virtual memory than physical RAM exists; if everyone touches it later, the kernel invokes the OOM Killer to terminate the highest oom_score process. Meanwhile, multi-threaded servers often swap glibc ptmalloc for jemalloc or tcmalloc to reduce heap fragmentation and arena lock contention."

4. Quick Interview Drill

Scenario 1 (Mid)

100 microservices run on one Linux host, each dynamically linked to a 2 MB libc.so. Roughly how much physical RAM does libc's code section consume?

Scenario 2 (Senior)

A C service calls char *p = malloc(1024 * 1024 * 1024); (1 GB) on a container with 512 MB RAM and never writes to p. Does it immediately crash?
