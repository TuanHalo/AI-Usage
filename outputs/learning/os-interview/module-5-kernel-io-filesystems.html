Module 5: Kernel Mode, Syscalls, Files & High-Speed I/O

Interactive Lesson Date: 2026-11-14 Agent: cs-mentor Fresher → Senior

Why can't your app read your SSD directly? Why does Linux treat a keyboard, a pipe, and a TCP socket as "files"? And how do Nginx and Kafka serve 1,000,000+ connections per second using epoll and sendfile()?

1. Daily-Life Analogies: Bank Security Windows & Shipping Labels

🏦 User vs. Kernel Mode = Bank Lobby vs. Bank Vault

Customers in the Lobby (User Space / Ring 3) aren't allowed to walk straight into the Vault (Kernel Space / Ring 0). Instead, you hand a request slip (System Call) through the security glass (CPU Trap) to the teller (Kernel)!

🏷️ "Everything Is a File" = Universal Shipping Label

Whether you're writing to an SSD, a terminal screen, a pipe, or a network socket, Linux gives you an integer ticket (File Descriptor) and the exact same 4 verbs: read(), write(), poll(), close().

🍽️ I/O Buffer = Carrying Plates on a Tray

Walking from the kitchen to a table 100 times carrying 1 french fry at a time (unbuffered syscalls) is exhausting! A Buffer is a serving tray: collect 100 fries in user space, make 1 trip across the kernel wall.

📦 Zero-Copy (sendfile) = Direct Conveyor Chute

Why pull a box out of the warehouse, carry it up to the manager's office, and carry it right back down to the delivery truck? sendfile() opens a direct hardware DMA chute from Page Cache straight to the Network Card!

3. Interview Question Deep-Dive (Fresher → Senior)

Fresher Core OS

Q1. User Mode vs. Kernel Mode: Why separate them?

🎙️ 30-Second Answer: "CPU hardware enforces privilege rings: Kernel Mode (Ring 0) can run any instruction and touch hardware/all RAM, while User Mode (Ring 3) is sandboxed to its own virtual memory. Separation stops a buggy or malicious user app from crashing the entire OS, formatting disks, or spying on other apps' memory."
Junior Core OS

Q2. What happens under the hood during a System Call?

🎙️ 30-Second Answer: "Your app calls a libc wrapper like read(), which puts the syscall number + arguments into CPU registers and executes a special trap instruction (syscall on x86-64). The CPU switches to Ring 0, saves user state, validates permissions via the kernel syscall dispatch table, performs the work, and executes sysret back to Ring 3."
Junior Core OS

Q3. Linux "Everything Is a File" & File Descriptors (FD)

🎙️ 30-Second Answer: "Through the Virtual File System (VFS), Linux exposes regular files, keyboards (/dev/input), terminals (0=stdin, 1=stdout, 2=stderr), pipes, and network sockets behind a uniform File Descriptor integer and read/write/close API. An FD is simply an index into that process's per-process Open File Table."
Mid Core OS

Q4. What is a Buffer, and why do we need User Buffers AND Kernel Page Cache?

🎙️ 30-Second Answer: "A User-space buffer (like C's FILE* or Go's bufio) batches tiny writes together to avoid expensive user↔kernel syscall overhead on every byte. The Kernel Page Cache buffers disk blocks in free RAM so repeated reads finish in nanoseconds and disk writes can be batched asynchronously (unless you call fsync() for durability)."
Mid Core OS

Q5. What happens when 2 processes read/write the same file simultaneously?

🎙️ 30-Second Answer: "If two processes independently call open() on the same file, each gets its own Open File Description with its own file offset—so concurrent writes at offset 0 can silently overwrite each other! Fix it using O_APPEND (atomic seek-to-end + write for logs) or advisory/range file locks (flock / fcntl)."
Mid Core OS

Q6. Why is a Socket a file? Unix Domain Sockets vs. TCP/IP Sockets

🎙️ 30-Second Answer: "Treating sockets as FDs lets apps reuse read/write/epoll identically for files and networks. A Unix Domain Socket (AF_UNIX) communicates between processes on the same host via a filesystem path (/var/run/docker.sock), skipping TCP three-way handshakes, routing, and packet checksums—making it ~2× faster than 127.0.0.1 loopback TCP."
Mid Production

Q7. Hard Links, Soft Links & Why Deleting an Open Log File Doesn't Free Disk Space!

🎙️ 30-Second Answer: "A Linux file's metadata & disk blocks live in an Inode. A Hard Link points directly to the Inode (incrementing its link count); a Soft Link stores a string path. The kernel only frees an Inode's disk blocks when BOTH link_count == 0 AND open_fd_count == 0—so if you rm app.log while Nginx still holds its FD open, df still shows 100% disk full until you restart/reload Nginx!"
Senior C10K Scale

Q8. I/O Multiplexing: select/poll vs. epoll (Level vs. Edge Triggering) & io_uring

🎙️ 30-Second Answer: "select/poll copy the entire FD array to the kernel and scan all N FDs every call—O(N). epoll stores FDs once in a kernel red-black tree and pushes ready events via driver callbacks into an O(1) ready list. In Level-Triggered (LT) mode, epoll_wait keeps firing while data remains; in Edge-Triggered (ET) mode, it fires only once on new data arrival—so you MUST use non-blocking sockets and drain until EAGAIN or your connection hangs forever! Modern Linux io_uring goes further with shared user-kernel ring buffers for true async file & network I/O."
⚠️ Senior Thundering Herd: Multiple worker threads sharing one epoll FD can all wake up on 1 incoming packet—prevent this with EPOLLEXCLUSIVE or per-thread SO_REUSEPORT listeners!
Senior C10K Scale

Q9. Explain Zero-Copy (sendfile()) — Why Is It "Zero-Copy"?

🎙️ 30-Second Answer: "Traditional read() + write() makes 4 context switches and copies data twice across the user/kernel boundary for no reason. sendfile() uses 2 context switches and keeps bytes strictly inside kernel space: DMA loads disk → Page Cache, and DMA pushes Page Cache → NIC directly—achieving 0 CPU copies."

Scenario 2 (Senior)
